A spec

## is a story, ### a rule, the quint block under it the rule's formal half. A definition's name gives its role.

spec/order.md

## Story: Check out

### A payment never exceeds the balance

A payment is a positive amount toward a
pending order. The payment that clears the
balance marks the order as paid.

```quint
pure def canPay(o: Order, amount: int): bool =
  o.status == Pending and amount > 0
    and o.paid + amount <= o.due

pure def pay(o: Order, amount: int): Order =
  val paid = o.paid + amount
  { ...o, paid: paid,
    status: if (paid == o.due) Paid else Pending }
```

### A pending order still has a balance

```quint
pure def alwaysPendingHasBalance(o: Order): bool =
  o.status == Pending implies o.paid < o.due
```

What a green check means

Proved

  • The initial state satisfies every always rule
  • Every transition keeps every always and step rule
  • Every law holds
  • Hand-written //@ ensures hold
  • Each sometimes goal is reachable, by a witness

Simulated

  • Generated TypeScript means the Quint
  • The shell works, by tests
  • Obligations a person accepted into spec/unproved.lock.json; the order example has none

Trusted

  • The Quint means the prose; review makes sure someone judged it
  • The generator, beyond replay
  • Quint, LemmaScript, Dafny, the shell
  • Built-ins unmodified; every //@ requires can hold
  • Sums stay below 253
  • Nobody edits gen/, the cache or the tools

When a proof fails

Proof finds a rule that is true but not inductive. Delete "Drafts and cancelled orders hold no money" and every trace still passes, but Dafny considers a draft that is already paid.

  • prove it in spec/<name>.proof.dfy, lemmas only
  • or, if no proof can help, state the missing fact as a rule
  • or the user accepts it as simulated: npm run accept -- unproved
