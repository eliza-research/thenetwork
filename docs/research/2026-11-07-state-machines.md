# State machines in The Network: synthesis and Quint plan

Date: 2026-11-07. Branch: `claude/quint-state-machines`, base commit a0ed7bc. This file is research only. It changes no code. Sections 1, 3, 4 and 6 are hand-written. Sections 2 and 5 are generated by a script from the 25 reports and a hand-written merge table.

**Result in numbers.** 252 machines after merge (105 P0, 77 P1, 70 P2), from 227 additional ids that several reports gave to the same machines. 510 suspected defects after merge (86 P0, 207 P1, 217 P2), from 610 report entries. 16 Quint modules are planned. 50 defects have no module: they need a corpus row, a sim gate, a lint or a doc fix.

No defect here is confirmed by this synthesis. All verdicts are `pending`. Report evidence levels differ: some defects were reproduced by a probe, others were found by reading only.

## 1. Method and coverage

**Readers.** 25 reports in `docs/research/state-machines/`: 16 package and area reports (`blooio-notify`, `capital`, `core`, `deploy-ops`, `engine`, `implicit-sweep`, `mcp-oauth`, `network-consent-core`, `network-harness`, `network-service-inbound`, `network-service-outbound`, `observatory`, `platform-consent`, `platform-identity`, `sim`, `sql-schema`), 3 journey reports (`journey-signup`, `journey-match`, `journey-exit-safety`) and 6 gap reports (`gap-active-member-journey`, `gap-app-journeys`, `gap-bias-monitor`, `gap-connector-journey`, `gap-console-client`, `gap-status-columns`). Total 18,384 lines, 1.35 MB.

**Coverage of this synthesis. The task asked for a full read of every file. That was not done.** A read call reported that the rest of a file did not fit in the context left, and 1.35 MB is too large to hold with the output that this task needs. So the coverage is not equal:

| Coverage level | Files | What was read |
|---|---|---|
| Read line by line, in full | `implicit-sweep`, `core`, `gap-status-columns`, `network-service-inbound`, `network-service-outbound`, `network-consent-core` | All lines. |
| Parsed by script, sections viewed | The other 19 reports | A script read the whole file and extracted the machine index and every defect block (title, locations, trigger, confidence, priority). I viewed the index tables, defect titles, and the Quint plan sections or journey outlines. I did not read their machine narratives line by line (state tables, invariants, failure analysis). |

**What was not read and why.** The machine narrative sections of those 19 reports. The reason is the context limit above. Effects:

- Sections 2 and 5 are complete for ids, because a script parsed all 25 files. A coverage check compares catalog ids with every index table.
- `~n` and `n/s` state counts in section 2 come from a script, not from a read. 100 machines have `n/s`. Treat all `~n` values as estimates. Wave 2 authors must read the owner report section.
- Duplicates can remain in section 5 among reports that were not read line by line, because the merge used titles for them. Two merges that join close but not identical defects are marked by the wider title (for example the row that joins `journey-match` M8 and `journey-exit-safety` JE18). Check these before fixing.
- Trigger text for the 19 reports is a script cut of the report text. It can stop mid-sentence, and a few rows hold the first sentence of the defect, not a true trigger. Read the source defect before acting.
- Priority: the highest stated priority of merged entries. Where a report gave none, I assigned one: `implicit-sweep` by the rule it touches; `capital` P2, or P1 and P0 for the entries that touch replay, forget, or age; `sim` P1 when its "effect on proof" column says yes or partly, else P2; `gap-bias-monitor` P1 for high severity, else P2.
- Each Quint module in section 6 reflects the Quint proposal of each report, but module authors must read `doc_refs` in `quint-plan.json` in full.

**Limits inherited from the reports.** The Eliza gateway and Eliza Cloud are upstream and not in this repository, so statements about them are unverified. The reports' scratch probes are outside the repository. I ran no test, no model and no database for this synthesis. I did not check any file:line against the code.

## 3. Cross-machine interaction map

The table lists shared state and required ordering. Each row can break even when each machine is correct alone.

| Link | Machines | Shared state or order | Failure if the link breaks | Defects |
|---|---|---|---|---|
| X1. Consent stores | `consent-ledger`, `opt-out-projection`, `gateway-consent-mirror`, `recycled-hold` | Four stores answer "may we text this person". Ledger write comes first. Projections lag. No transaction spans them. | Stores disagree after a crash or late message. | SD-001, SD-104, SD-023, SD-130 |
| X2. Turn and effects | `signed-turn`, `consent-ledger`, `store-unit-of-work`, `text-join`, `collected-reply` | The claim commits first. Each effect commits alone. Undo runs on an exception, not on a crash. | Partial effects with a refused retry. | SD-001, SD-128, SD-011 |
| X3. Belief and truth | `send-belief`, `send-pipeline-and-deferred`, `outbound-queue-row`, `message-status-mirror`, `notify-item`, `booked-attendance` | `onSent` means "written to the queue". `storeStatuses` writes `network.messages.status` only. No code in `packages/network/src` reads it. | The Network acts on sends that never happened. | SD-006, SD-030, SD-095, SD-257 |
| X4. Deferred outbox before the queue | `send-pipeline-and-deferred`, `relay-swap`, `booked-attendance` | A deferred send sits in `network_state`, before queue admission, with no hook on refusal. | One-way number, late consent, lost reveal. | SD-007, SD-146, SD-248 |
| X5. Answer routing | `routing`, `awaiting-slot`, `opp-participant-status`, `yes-hold`, `reply-reader` | Route picks the app. The one slot picks the item. The reader picks the meaning. All three decide a consent. | A reply reaches the wrong item or reads as a yes. | SD-028, SD-077, SD-043, SD-041, SD-033 |
| X6. `dropMember` hub | `trust-level`, `safety-report`, `member-age-policy`, `opt-out-projection`, `opportunity-lifecycle`, `awaiting-slot` | Every safety machine enters consent machines through `network.ts:2564`. It has one branch per stage. | Bad notices, stale slots. | SD-047, SD-048 |
| X7. Person against member id | `person-safety-carryover`, `trust-level`, `safety-case`, `erasure-saga`, `membership`, `age-floor` | Safety state lives per (app, member). Identity lives per person. | X8. Sagas with no retry | `ban-saga`, `erasure-saga`, `phone-identity-hold`, `oauth-forget-revoke`, `photo-object`, `clef-rating` | Each step is its own commit, in a set order. Listeners run on some paths only. | Residue, or a saga that cannot finish. | SD-005, SD-016, SD-089, SD-052 |

## 6. Quint model plan (wave 2)

### 6.1 Rules for all modules

- Files go under `quint/` in the repository. `quint/` does not exist yet. Wave 2 creates it.
- 16 modules, ordered P0 first by the order of risk. Each module has one file, so authors can work in parallel with no shared files.
- **No shared `quint/common` module.** It is not truly needed. Each module defines its own small types, so that no author waits for another. The cost is some repeated type text. Where two modules share a fact (for example `opted_out`), each module takes it as a nondeterministic input.
- One SQL transaction is one atomic action. Each `await` between transactions is a possible crash and interleave point. Row locks are implicit.
- Regex readers, the leak guard, HMAC, Clef and matching scores are oracles. Quint checks what a misread can reach. Corpus rows test the readers. Quint will not find defects in the reading itself (SD-031, SD-032, SD-034, SD-033).
- Time is an integer tick with named thresholds. Skew is a bounded offset per side. Ids and hashes are small ids.
- The gateway is a nondeterministic retrier. Each assumption about upstream is written as an assumption, not as a fact.
- Each module has at least one reachability witness, so that a vacuous pass is visible.
- Before each invariant, state the rule it comes from (AGENTS.md item, PRD section). For a defect the model reproduces, set the Verdict in section 5. A reproduced defect needs an integration, e2e, sim gate or corpus case for its fix. The repo has no unit or smoke tests (docs/tests-policy.md).


### 6.2 `quint/turn_consent.qnt` (P0)

- **Machines (19).** `signed-turn`, `sender-serialization`, `consent-ledger`, `gateway-consent-mirror`, `opt-out-projection`, `optout-reader`, `stop-hint-window`, `agent-signal-review`, `recycled-hold`, `journey-stop-start`, `eliza-takeover`, `webhook-intake`, `active-member`, `route-authority`, `legacy-inbox-row`, `routing`, `open-turn-binding`, `agent-context-projection`, `participation-window`.

- **Key actions.** `sendText(kind, receivedAt)` with kinds stop, stopLikely, start, leave, help, other; `claim`, `renewLease`, `commitLedger`, `commitProjection(app)`, `collectReply`, `complete`, `throwInTurn`, `crash`, `retry`, `sweep`, `deliverResponse` (lossy, can repeat), `staffResolve`, `proposeSignal`, `tick`.

## 7. Top risks

These are ordered by the rule they touch. Each one is suspected, not confirmed.

1. **STOP can be lost or delayed.** SD-001, SD-002, SD-031, SD-024. A crash after the claim gives a refused retry; a running turn refuses STOP; "STOP STOP" is not read as a stop.
2. **Consent can be assumed.** SD-041, SD-008, SD-075, SD-006. A counter reads as yes; a group falls to a named pair; a yes cannot be taken back; silence confirms a plan the member never saw.
3. **The production tick omits retention and inbox work.** SD-003. Wiring purge without care then activates SD-004.
4. **Safety does not follow the person.** SD-021, SD-022, SD-074. A leave and a rejoin clear a hold.
5. **Ban is partial.** SD-005, SD-019, SD-013, SD-073.
6. **Minor rules have gaps.** SD-010, SD-038, SD-011, SD-014, SD-065, SD-066.
7. **Number swap can go one way.** SD-007, SD-039.
8. **Staff console can act on the wrong person.** SD-068, SD-069, SD-082.
