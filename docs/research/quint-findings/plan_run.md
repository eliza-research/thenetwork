# Quint findings: `quint/plan_run.qnt`

Module plan: [2026-11-07-state-machines.md](../2026-11-07-state-machines.md) section 6.7 (P0). Machines: M-045
`plan-run`, M-046 `plan-fallback`, M-124 `crew-offer-and-crew`. The model follows the code at `ad67275`.
This file is hand-written. The traces are generated by the Quint simulator and shortened by hand.

## 1. What the model contains

- **Code.** `packages/engine/src/plans.ts` (startPlanRun, recordPlanAnswer, checkPlanDeadline, planFallback,
  crewOptIn, crewSessionPlan) and `packages/network/src/network.ts` (beginPlan, planLane, planProbe, planAnswer,
  planAct, bookPlan, planReveal, planJoin, planFallback, planOut, dropMember, handleDrop, close, the
  `plan_probe` and `reveal` send hooks, checkRecipient, busy, bookedNear, crewSessions, resolveCrew,
  onCrewAnswer, applyBlock, and the intro `reveal`).
- **Actions.** One inbound message, one tick, one review decision or one actor event is one action (the
  ConsentNetwork is in memory and has no `await` inside a handler). `probe` is its own action because the send
  window, one-a-day and the allowance only defer a plan probe. Actor events: STOP, trust watch, minor signal,
  block, "can't make it", an intro for a plan member (probe, yes, book), crew answers, crew sessions.
- **Oracles.** The probe copy leak gate (`buildPlanProbe`), the send-time leak guard, the Blooio streak
  (`canSendLogistics`) and "a matching public event exists".
- **Bounds.** Members a-e. One group plan: invited a, b, c, d; bench e; quorum 3; `groupSize[0]` 2 or 3. Hours
  are small integers: deadline 4, late-join cutoff 7, start 10, probe silence 3. Crew a, b, c, weekly slots 0-4.
  Partner plans are not modelled (no register defect of this module needs them, and the network never runs the
  fallback's `partnerPlan`).
- **Invariants.** 17, all in `val safety`. `val guards` is the subset that must hold today (minors, blocks,
  STOP, review, crew opt-in).
- **Run tests.** 11 concrete traces (`quorumBooksTest` and one per defect below).

## 4. Register defects of this module that the model cannot reach

- **SD-264** (one "neither" closes a whole group). The trigger is the time-options path of non-plan group
  intros (`onProbeAnswer`, `declinedTimes`, network.ts:2297-2313). Plan probes carry no time options. It
  belongs to the opportunity model (`quint/opportunity.qnt`).
- **SD-425** (friends: probe deadline can equal now). The trigger is `packages/sim/src/apps/friends/planner.ts:49`,
  the local friends planner, not the network plan run. The model starts from an approved plan with a deadline
  after now.

Not in this task's list, for the record: SD-205, SD-211, SD-331 and SD-424 are refuted in the register. The
model agrees with SD-211 and SD-331 being harmless: `noContactAcrossBlock` and `noMinorContact` hold, because
the send-time check refuses the probe or reveal. SD-046 and SD-204 also interact: in the SD-046 register trace,
a and b fell to `plan_copy`, which is the SD-204 path.

## 5. Model choices that matter for the results

- `yesSayerTold` exempts members who left on their own or by policy, and a plan closed for the minors policy
  or a block. Code comments (dropMember network.ts:2568-2571, applyBlock network.ts:1437) say that any later
  message about such a plan is a minor contact or says why, so silence there is by design.
- `probe` is enabled only while probing before the deadline, or while booked until the cutoff: advance() runs
  checkPlanDeadline before planLane (network.ts:3365-3369).
- An open intro (probing, yes or booked) makes the member busy for plan probes, as `busy()` does
  (network.ts:4373).
- The first draft of `noMinorContact` read the historical `seated` set. That was a model error (a member who
  becomes a known minor after booking is dropped, not seated); the invariant now reads the current yes-members of
  a booked plan.
