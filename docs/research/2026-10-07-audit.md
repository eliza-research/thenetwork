# Repo audit, 2026-10-07

Read-only audit of `packages/*`, `prototypes/*`, `scripts/*`, `docs/*` and `data/synthetic`, checked against the founder decisions (minors join but are never connected; five connector tools; Blooio line +18087881821; ntwrk.love on Cloudflare; gpt-6-luna via Surplus for all LLM use; private repo; synthetic profiles only; teen-safe ChatGPT surface; no mcp.ntwrk.love deploy until approved; human review of proactive matches under ~1,000 members; no cold outreach; quiet hours; auto-pause after two unanswered; Blooio limits of 3 unanswered per conversation, one re-engagement after 14 days, and 20-50 new conversations per day per line).

Nothing in the repo was edited apart from this file. Line numbers refer to the working tree on 2026-10-06 evening. That tree has uncommitted work in `packages/engine/src/judge*.ts`, `config.ts`, `core/llm.ts` and the sim files, plus untracked `packages/network`, `packages/observatory` and `prototypes/prompt-opt`.

## Summary

- **No P0 in shipped-to-users code.** Nothing here is live. Every P0/P1 below blocks the pilot rather than describing a live incident.
- **Minors are never introduced.** No code path introduces a minor to another person: engine filters, the ConsentNetwork `eligible()`, the stub network and the connector visibility rules all exclude them, and a 10-day ConsentNetwork run showed 0 minor contacts. There are gaps in how minors are *detected* and *re-checked* (see P1-4 and P1-5), and the observatory UI lets a known minor be proposed.
- **No canary leaks found.** No canary token appears in any outbound message, in committed result files or in `docs/results/*`. The run logs under `runs/` (gitignored) contain canaries as judge ground truth.
- **No secrets in tracked files.** The only key-pattern hits are fake test tokens in `reference/eliza-homepage/tests/e2e/telegram-return.spec.ts:57,158`. `.env` is gitignored and untracked. The Cloudflare `account_id` appears in `wrangler.toml:11`, `scripts/wrangler.sh:5` and `.env.example:23`; it is not a secret.
- **`data/synthetic` is clean.** All 500 phone numbers are 555-01xx and all 500 emails are example.com. There are no addresses or real-person names. Canaries appear only in `facets.jsonl` and `hidden_truth.jsonl`, as designed.
- **Typecheck passes:** `tsc --noEmit -p .` is clean.
- **Tests:**
  - Offline full suite (`bun test packages prototypes` with API keys blanked): 642 tests, 631 pass, 9 skip, 2 fail, **78 s**.
  - Same suite with the root `.env` loaded (live LLM tests on): 639 pass, 1 skip, 2 fail, **221 s**.
  - Both failures are in `packages/network/test/network.test.ts`; see P2-20.
  - The reported hang (over 30 minutes) did **not** reproduce. Likely causes are in [Ops](#ops-test-hang-ci-wrangler).
- **Three founder rules are not enforced on the path that actually sends messages:**
  - human review of proactive matches;
  - the 3-unanswered limit and the single 14-day re-engagement;
  - quiet hours for non-proactive texts.

  The engine and Blooio prototypes contain pieces of these rules, but nothing wires them together.

### Full-suite hang

The hang did **not** reproduce today.

| messaging-blooio | 0.4 s |

An earlier per-package run from *inside* each package directory took 0-3 s for most packages. That is the key difference: Bun loads `.env` from the current directory, so **the full-suite command (run from the root) turns on every live LLM test and the per-package checks (run from package dirs) don't.**

Likely causes, in order:

1. **Live LLM tests with no request timeout (P1-12, P1-15).** `core/llm.ts` has no default `timeoutMs` and retries 4 times with backoff. During a Surplus slowdown or 429 storm, each live test waits out its per-test timeout. Those timeouts add up to about 1,050 s (judge 300+120, sim 90+180, engine 180, 3 × 60 core smoke), and the abandoned fetch/retry loops keep running in the background of the same process.
2. **Shared `network_test` Postgres (P2-21).** `testDb()` runs `DROP SCHEMA network CASCADE` with no `lock_timeout`. If another session's test run or observatory process holds a lock on that schema in the same cluster (port 54339), the DROP waits indefinitely. This is consistent with the tree being shared by several sessions.
3. **Environment pollution (P2-19).** `real.test.ts` leaves `DATABASE_URL="undefined"`, so any later `RealSource({})` in the same process tries to connect to a bogus database.
4. **Uncleared interval if a test fails.** `observatory/test/game.test.ts:116` starts a `setInterval` that is cleared only on the success path; if `await stepping` throws, the 10 ms interval keeps the process alive.

Fixes: P1-12 (default timeout), P1-15 (`RUN_LIVE=1`), P2-21 (per-run database and `lock_timeout`), P2-19, and `try/finally` around the interval. Then add `--timeout 120000` to the root `test` script.

### CI

There is no CI: no `.github/` directory exists. Proposed `.github/workflows/ci.yml`:

```yaml
name: ci
on: [push, pull_request]
jobs:
  offline:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    env: { RUN_LIVE: "0", SURPLUS_API_KEY: "", OPENAI_API_KEY: "", CEREBRAS_API_KEY: "", BLOOIO_API_KEY: "" }
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v2
        with: { bun-version: 1.4.2 }
      - run: bun install --frozen-lockfile
      - run: bun run typecheck
      - run: bun test packages prototypes --timeout 120000
      - run: ./scripts/wrangler.sh deploy --dry-run --env="" -c prototypes/connector-mcp/wrangler.toml  # needs no credentials for dry-run
  live:
    if: github.event_name == 'workflow_dispatch' || github.ref == 'refs/heads/main'
    needs: offline
    runs-on: ubuntu-latest
    timeout-minutes: 30
    env: { RUN_LIVE: "1", SURPLUS_API_KEY: "${{ secrets.SURPLUS_API_KEY }}" }
    steps: [ ...same setup..., { run: "bun test packages --timeout 300000" } ]
```

Postgres-backed observatory tests skip when `pg_ctl` is absent, which is the case on a stock runner. To run them in CI, add a `services: postgres` block and point the tests at it. Never give CI the OpenAI or Blooio keys; the Blooio live test also stays manual.
