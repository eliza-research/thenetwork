## C. Model errors

- E1. `refusedItemsStayPending` (qnt:406-409) counts only `refused`/`expired`, and `refusedNotCounted` (qnt:399-401) only `refused`/`expired`/`dropped`. A digest that ends `obsolete` because one app was erased (retention.sql:104-109 trims the delivery, `stillNeeded` fails on the id hash, scheduler.ts:210) leaves the surviving items notified, never sent and counted. The rule (scheduler.ts:3-5, PRD 32.9) is broken but both invariants pass (probe above). The invariants are weaker than the rule; widen them to every non-sent terminal status.
- E2. `noRepeatOfNetworkText` (qnt:390-392) holds by construction: projRecord's else branch always writes `notified: "net"`. The code (pg-store.ts:71-80) commits the inserted item unnotified when `deliveryIn` returns false (delivery id `net:<id>` already present, or the delivery trigger drops the row), and the scheduler would then text it again (the SD-151 shape). No current trigger was found (message ids are unique, `net:` deliveries are deleted with their one item), so this is a vacuity, not a defect. Model the refusal branch, or make `addDelivered` roll back when it created an item and could not record the delivery.
- E3. `reread` keeps `via` (qnt:199). Drift already fixed on claude/formal-main; port it.
- E4. `vouchCreditFollowsValue` (qnt:798-807) omits the code's conditions `not safetyFlagged`, `not removed`, `t - joinedAt <= 30 days` (ledger.ts:168, 363-364). Harmless only because the model has no such events or time; it becomes wrong as soon as G10 is added.
- E5. `leave` and `projRecord` treat the platform and network removal as one state `ms`; the inbox trigger also checks `platform.people.deleted_at` and `network.members.account_status` (retention.sql:13-22). The model cannot reach D1.
- E6. `replayEqualsLive` (qnt:778-779) is a one-process property. The SD-153 fix replays by `seq`, which is insert order of one process, not accepted order across processes (D2). The findings file says the fix gives "accepted order"; that holds only with one writer.

## D. Suspected new defects

- D1 (P2). Projection head-of-line block. runtime.ts:697-716 selects the 50 oldest unprojected outbound messages of live network members; a row whose `addDelivered` throws is only logged and is selected again first on every drain. Trigger: platform `forgetMembership` (platform pg-store.ts:343-352: membership `removed` + `forget_data`) or `deleteAll` (people `deleted_at`, memberships deleted) commits, and the network-side forget unit has not run or failed (two transactions, G5). Each accepted-but-unprojected message of that member now makes `notify.guard_inbox_member` raise "Notify membership is unavailable". With 50 such rows in one app (several stalled erasures, or one member with many accepted texts), no later text of any member in that app is projected: their assistants never see them (`everyNetworkTextInInbox`), and their proactive texts do not count toward the weekly cap. Depends on how often the erasure saga stalls (identity_sagas). Fix: skip or mark rows whose scope is erased (check `lock_live_scope` in the select), or order the retry after fresh rows.
- D2 (P2, latent: reader off). Replay drops stored events across replicas, silently. `seq` is an identity value taken at insert (migration 0057:10). Replica A (clock ahead, or a later unit) inserts an event with t=100 at seq n; replica B inserts its own event with t=98 at seq n+1 (B's own ledger accepted it: lastT 90). After a restart, the replay in seq order refuses B's event (t < lastT, ledger.ts:135) and runtime.ts:364 swallows it with an empty catch; `/health` reports `capital.rejected` from the wiring counter (runtime.ts:847), which does not count replay rejects, so it shows 0 while the ledger lost an event (capital-3 says any reject must fail). Same-t pairs (help_given/help_confirmed) of two replicas can also interleave. Related to SD-345 (refuted) and SD-153/SD-156, but the trigger (two writers) is new. Fix: count replay rejects in health; or order the replay by (t, seq) and stop the per-replica ledger (single ledger writer).
- D3 (P2, one-shot). Migration 0057 numbers existing rows "in table order" (its own comment). After forget deletes (runtime.ts:576) and vacuum, later inserts reuse freed heap slots, so physical order is not insertion order. A database that had capital events before 0057 can get a later event a lower seq than an earlier one; the replay then refuses the earlier one (t < lastT) or splits a same-t pair. Latent (reader off). Fix: backfill seq with `order by t, <old insert hint>` in the migration, or accept and document.
- D4 (P2, sim/edge). `age_updated` id reuse (G11): minor -> cleared -> minor in one Clock tick reuses `age_updated:<id>:minor:<t>`, the ledger skips it, the member stays eligible as a minor. Trigger: staff `clearMinorSignal` and a new minor signal in the same millisecond, or the sim's discrete clock where both land in one step. Fix: put a per-member counter in the key.
