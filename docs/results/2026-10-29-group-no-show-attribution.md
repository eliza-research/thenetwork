# Scope group no-show penalties to identified members

Date: 2026-10-29. Base: `a0ed7bc6495d9e524afc3d500738212a28dc7bc2`.
Fix and regression: `039052c8af2880d1eff53e4634898a6712d32cf5`.
Local combined code: `63f622ea4839c01cdb7c77dd7edd09142ea2d2a3`.

## Requirement, problem and cause

Reproduced bug under the approved Slop scope. PRD 15.2 requires contextual
reliability evidence; PRD 28's learning rules require corroborated negative feedback.
A missing reply alone does not identify someone as absent.

Ana, Ben and Cara consent to a reviewed group booking. Ana later says
"Ben didn't show up." Ben and Cara leave their check-ins unanswered. After
four days, main adds a no-show to both Ben and Cara. "Someone didn't show up"
also penalizes both. Planner-generated hikes have the same problem.

The finalizer checks whether any attendee reported a missing person. It applies
that report to every silent member. It already stores names from feedback but
does not use them to limit these reliability penalties.

## Fix and alternatives

Require a group report to name the member before counting their unanswered
check-in as a no-show. Pairs retain their existing single-counterpart rule.
In both ordinary and planner feedback, "Nobody else came" and "No one else
showed up" populate the existing name list with all counterparts.

The four-day wait, self-reported absence, attendance replies, and corroborating
positive replies retain their existing behavior. No new storage field, package,
copy, client contract or dependency. The capital ledger's pair-only inference
rule is unchanged.

Alternatives considered:

1. Ignore every group no-show report. That also loses named and explicit
   everyone-absent evidence.
2. Add a separate persisted all-absent flag. The existing missing-member list
   already represents the required identities and survives JSON restarts.

## measurement

One new gate: `group attendance: a no-show report identifies the silent member`. Hand-written synthetic cases,
seeds **1, 2, 3**, eight replies in each of three real workflows:

- A reviewed pair introduction.
- A reviewed three-person group introduction.
- A four-person hike generated by the real planner.

The replies cover unnamed and named absence, two everyone-absent phrases,
positive feedback, self-reported absence, a disputed report, and another
attendee's positive confirmation. Each workflow onboards adults, reviews the
proposal, obtains consent, books, delivers feedback questions, and finalizes.
Four JSON process restarts check persistence and confirm that finalization does not count a penalty twice.
The gate also checks that no counterpart receives a penalty before finalization.
The test uses a simulated staff reviewer with `review: "human"`; no live messages.

2. Load `scripts/sim/network.ts` from `039052c8af2880d1eff53e4634898a6712d32cf5`.

4. Load `packages/network/src/network.ts` from the same code commit and repeat.
5. Expect 153/153 and 72 correct `GROUP_ABSENCE_OUTCOMES` rows.

Existing name matching remains unchanged. This does not resolve duplicate first
names, quotations, or mixed clauses naming both present and absent people.
Already-finalized penalties are not repaired. Older unfinalized group records
without identified missing members are treated as unspecified reports; their
original text is not retained, so an old everyone-absent statement cannot be
reconstructed. No live sends or deployment. Draft pending review and hosted CI.
