# Keep discarded simulations out of a reset world

## Problem and scope

Resetting a game while a controlled member has a pending reply corrupts the new
world. The old step resumes when `dispose()` releases that member. Before this
fix, reset replaces the world, projector and store before the old step finishes.
Its remaining event callbacks then write into the replacement store.

This is a reproduced simulation defect under CONTRIBUTING 3.1 and the approved
Slop scope. PRD 34.3 requires reproducible runs that can be inspected in the
console. `docs/observatory.md` section 4 describes controlled members and levels
that restart the world. A reset must show the selected world, with no events from
its predecessor. No UI, copy, matching policy or live service changes are made.

Base: `a0ed7bc6495d9e524afc3d500738212a28dc7bc2`.
Runtime: Bun 1.4.2 on Windows. PostgreSQL 16.15 is used by the required suites.
All data is synthetic. Offline worlds use the simulated reviewer.

## Cause and fix

`GameSource.dispose()` stopped timers and awaited `TakeoverAgent.releaseAll()`.
That answers pending prompts, but does not wait for the enclosing `World.advanceTo`
call. The callbacks close over the `GameSource`, whose fields reset replaces.

After releasing the members, await the existing advance promise before disposal
returns. Reset can then initialize its replacement. The old finite step still
runs to its requested endpoint, as it did before, but its events stay in its own
store. Shutdown also waits for that work instead of leaving it in the background.

Alternatives:

1. Drop callbacks whose world has been replaced. That leaves discarded work
   running and requires guards on both event and engine-run callbacks.
2. Cancel the world scheduler. That needs a cancellation contract through the
   scheduler and pending persona replies. The existing step promise provides the
   required lifecycle boundary without that change.

## Limits

Reset and shutdown now wait for the current finite step to finish. A long step
can delay their response. This does not add cancellation or a timeout to World,
and does not fix arbitrary concurrent resets. No production data or raw member
conversations are included in this report.

## Reproduce the paired measurement

Save the following program outside the checkout as `reset-drain-measure.ts`.
Run from each checkout with the same file and separate output paths:

```powershell
$env:RESET_DRAIN_OUTPUT = '../reset-drain-measure-before.json' # after.json on the fixed checkout
bun run --conditions eliza-source ../reset-drain-measure.ts
```

```ts
import { pathToFileURL } from "node:url";
const root = process.cwd().replaceAll("\\", "/");
const { GameSource } = await import(pathToFileURL(`${root}/packages/observatory/src/sources/game.ts`).href);
const { computeMetrics } = await import(pathToFileURL(`${root}/packages/sim/src/judge/metrics.ts`).href);
const DAY = 86_400_000, output = [];
const hash = (value: unknown) => new Bun.CryptoHasher("sha256").update(JSON.stringify(value)).digest("hex");
function snapshot(g: InstanceType<typeof GameSource>) {
  const s = g.state();
  const runs = s.engineRuns.map(({ wallMs, timingsMs, ...run }) => run);
  const value = { now: s.clock.now, members: s.members, opportunities: s.opportunities, runs,
    stats: s.stats, game: s.game, requests: s.requests, edges: s.edges, channel: g.world.channel.all() };
  return { hash: hash(value), now: s.clock.now, joined: s.stats.joined, messages: s.stats.messages,
    ownChannelMessages: g.world.channel.all().length, opportunities: s.opportunities.length, runs: runs.length };
}
for (const personas of [24, 80]) for (const seed of [1, 7, 11, 23]) {
  const opts = { seed, personas, days: 8, pushMs: 3_600_000, tickMs: 3_600_000 };
  const game = new GameSource(opts), fresh = new GameSource({ ...opts, seed: seed + 1 });
  try {
    await game.init();
    for (const m of game.state().members) await game.control({ type: "takeover", memberId: m.id, on: true });
    const old = game.world;
    const step = game.control({ type: "step", ms: 7 * DAY });
    const deadline = performance.now() + 10_000;
    while (!game.state().game?.prompts.length && performance.now() < deadline) await Bun.sleep(1);
    if (!game.state().game?.prompts.length) throw Error("No native takeover prompt");
    if (!(await game.control({ type: "reset", seed: seed + 1 })).ok || !(await step).ok) throw Error("Control failed");
    await fresh.init();
    const reset = snapshot(game), expectedReset = snapshot(fresh);
    if (!(await game.control({ type: "step", ms: DAY })).ok || !(await fresh.control({ type: "step", ms: DAY })).ok) throw Error("Replacement cannot step");
    const advanced = snapshot(game), expectedAdvanced = snapshot(fresh);
    const metrics = computeMetrics(old.records, { requireReview: true });
    output.push({ personas, seed, resetSeed: seed + 1, reset, expectedReset, advanced, expectedAdvanced,
      resetMatches: reset.hash === expectedReset.hash, advancedMatches: advanced.hash === expectedAdvanced.hash,
      oldMessages: old.channel.all().length, oldChannelHash: hash(old.channel.all()),
      oldRecordTypes: old.records.reduce((a: Record<string, number>, r) => { a[r.type] = (a[r.type] ?? 0) + 1; return a; }, {}),
      safety: { invariants: metrics.invariants.total, canaryLeaks: metrics.privacy.canaryLeaks, minorContacts: metrics.safety.minorContacts },
    });
  } finally { await game.dispose(); await fresh.dispose(); }
}
await Bun.write(process.env.RESET_DRAIN_OUTPUT!, JSON.stringify(output, null, 2));
console.log(JSON.stringify(output.map(({ personas, seed, resetMatches, advancedMatches, reset, oldMessages, safety }) =>
  ({ personas, seed, resetMatches, advancedMatches, ghostMessages: reset.messages - reset.ownChannelMessages, opportunities: reset.opportunities, oldMessages, safety }))));
```
