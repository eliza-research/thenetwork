# Quint flow models

The [product stories](../product/stories.md) describe the member and staff flows. This directory holds their existing standalone Quint state machines. Each Markdown file contains the flow, its safety scope, and one executable `quint` block. Change the Markdown source when you update a model.

The 30 modules came from `claude/quint-state-machines` at `30d950e1d6fa027a67b94cc6b03ba379dc923a63`. That source revision also contains the research plan and findings referenced in comments. Their comments document bounds, abstractions, excluded cases and drift. A code location in a comment names a file and a function. The chatjson_loop comments also give `llm.ts` line numbers, compared on 2026-11-18. The peon_manager_questions module was added later on develop.

## Run the models

```bash
pnpm run spec:setup
pnpm run quint:check                         # typecheck, replay traces, simulate safety and reachability
pnpm run quint:check turn_consent            # one model
pnpm run quint:check --tangle-only           # write the model blocks to runs/quint-models/
pnpm run quint:check --verify --jobs 2       # include bounded Apalache checks, requires Java 17+
```

The Whole-flow Quint workflow checks changed models at their configured
bounds. It checks every model when a shared tool input changes, the
comparison commit is unavailable, or it cannot restrict the input to
independent modules. Run the workflow manually to check every model from
an empty run directory. The local `--verify` option still adds Apalache.

A `witness_*` assertion is the negation of an expected reachable state. A witness check passes when the simulator reaches that state and the assertion fails. A witness can also use a named trace declared by `// quint-witness: witness_name runName`. That trace must end with `.expect(not(witness_name))`, and the checker requires the named run to execute and pass. Random simulation and bounded model checking still check safety within the run bounds.

These models use mutable variables, actions, nondeterministic environment steps, or executable traces. Vibespec generates TypeScript from pure definitions and guards in top-level `spec/*.md`. Keep whole-flow checks here while moving pure policy definitions into the Vibespec specs. When a generated policy takes over a production decision, compare its behavior with the corresponding action guard and keep the sequence, failures, and retry behavior in the flow model.

The [source coverage ledger](baseline/coverage.md), [drift record](baseline/drift.json), [LemmaScript file list](baseline/LemmaScript-files.txt), and [Dafny proof sources](baseline/proofs/) record the original relationships among models, code, and obligations. The historical proof sources include manually added lemmas and are scoped to the original branch. Vibespec's checks prove its own generated modules and eligible source files.

The frontend and agent flows have no imported model in this directory. Their state machines are top-level Vibespec specs: [landing entry](../landingEntry.md), [site pages](../sitePages.md), [brand identity](../brandIdentity.md), [browser join](../browserJoin.md), [connector authorization pages](../authorizationPages.md), [connected assistants](../connectedAssistants.md), [agent signup](../agentSignup.md), [connector tools](../connectorTools.md), [agent entry](../agentEntry.md), [staff sign-in](../staffSignIn.md), [console navigation](../consoleNavigation.md) and [console workspace](../consoleWorkspace.md). [Stories F37–F51](../product/stories.md#story-f37--know-which-app-i-am-joining) link to them. For the browser join page, which only peon.biz keeps, `browserJoin` is the current model. The other frontend specs add the view layer to [oauth_mcp](oauth_mcp.md), [console_views](console_views.md) and [staff_console](staff_console.md). ### photos_rating notes

The model follows `packages/platform/src/photos.ts`, `photo-upload-link.ts`, `packages/network/service/photoIntake.ts`, `service.ts` (`hooks().onForget`, `ageLowered`, `verifiedAdult`, `dropRatings`, `writeRating`, `verify`, the staff ban, `exportMember`) and `packages/platform/src/accounts.ts` (`recordAge`, `leave`, `deleteAll`): bytes before the row, the reserved row under the person lock (`uploadReserve`, `uploadRow`, `uploadDiscard`), `deleteFor` as one hide under the lock (`hideAll`) followed by bytes, rating and row per row, the photo deletion on a failed staff age check (`verifyList`), one pass of the retention sweep (`sweep`), the DELETE PHOTOS text command (`deletePhotosCmd`, `deletePhotosDone`, `deletePhotosErasesAll`), the upload link with its consent box, and the appearance exclusion in `memberExportFacetAllowed`. The probe sends text only (`probeCarriesNoPhoto`).

The state rules are checked in every quiescent state (no request in flight) of a trace with no crash, except while the ghost `raceResidue` is set (an upload reserved inside the leave or delete-everything window). The crash and that window are eventual exceptions: `sweepRepairs` checks that one sweep pass from every quiescent state leaves a state where every state rule holds, and `witness_sweepNeeded` and `witness_raceResidue` show that such states are reachable. `countLimit`, `bytesAlwaysHaveARow` and `storedRowHasBytes` hold in every state. `leaveSticks` and `banSticks` hold with no exception: the consent writes of `PhotoIntake.consentAnswer` and `PhotoUploadLinks.redeem` are one guarded statement. The ghost `ratingLeft` names the rating that a crash in a staff ban after its commit keeps until the staff retry drops it (`banCrashResumedTest`, `residueEndsAfterDropTest`). The boundary cases are in `packages/platform/test/photos.test.ts` and `packages/network/test/service-safety.test.ts`.

Outside the model: the under-13 branch of `ageLowered` (`finishUnderageCleanup`); the start check of `upload` is merged into `textPhoto` and `linkRead`; the sweep's batch limits (64 rows and 64 holders a tick). Abstractions: one `rate()` at a time (the code can overlap two; the version-bound discard in `writeRating` keeps the newer score); one sweep pass is one step, and its fifteen-minute wait is "the request that owns the change has ended".

### Identity models

- phone_identity models number keys and bans only; which sessions a number keeps when it gets a person (a join, an invitation or a number change) is in auth_edge. The normalizers are `normalizePhone` (platform) and `normalizeAddress`/`toE164` (blooio); their contracts were checked by reading. A banned number still gets the STOP, HELP and app-leave answers (`checkLineBan`); the model leaves these compliance answers out.
- cloud_auth: a join with no joining session ends every person-less session of the number (`attachPerson`), and `ae3IntendedRevokesTest` shows that a Cloud request answered "valid" before a reassignment acts for nobody. Carrier aging is a named environment assumption, ASSUME_CARRIER_AGING (no code enforces it): `recycle` in `step` takes it and ASSUME_CLOUD_PHONE_CURRENT; `recycleUnaged` and `recycleStale` drop them, and `w3_126NullGrantTest` is the counterexample (a null-person grant acts for the new holder). The assumption does not hold for staging-local, whose callback has no one-hour cap on the Cloud proof (open drift; the model uses one hour for every mode). `parseNetworkDelegation` allows the 30 s of `cloudIdentityTimesValid`, as auth_edge does. `max-samples` is 40000 so that `witness_lateBanGrantValid` stays reachable.
- auth_edge: one proxy secret; rotation is one transaction with a re-read (`rotateCommit`); `OtpService.start` counts a start in all four buckets or in none (`PeopleStore.hitAll`, `otpRefusedNotCounted`); a banned number is counted like any number and its send is withheld; the under-13 decline ends person-less sessions; `numberChange` (movePhone) and `invite` (createPerson) end the person-less sessions of the number that gets the person.
- join_age: every stated age is recorded before any other step (`recordStatedAge` of the [text enrollment spec](../textEnrollment.md)); an allowed age is recorded before the home-city question; a repeated join of an active membership without a network member runs the join hook again (`AwaitingRepair`); a failed join runs `onForget` (`undoFailedJoin`); an under-13 join deletes the pending texts (`endUnboundAccess`); a text join keeps the member id (`textJoinKeepsMemberId`); a text with no age and a phone floor under the join age gets the decline (`floorRefused`). Not compared again: the route rules, the unit age writes, the minor welcome and interview, the first-contact notice and the age-0 floor.
