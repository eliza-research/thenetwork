The [product stories](../product/stories.md) describe the member and staff flows. This directory holds their existing standalone Quint state machines. Each Markdown file contains the flow, its safety scope, and one executable `quint` block. Change the Markdown source when you update a model.

The source revision also contains the research plan and findings referenced in comments. Some code locations still need a new comparison with the runtime on this branch. On 2026-11-22 the stale references in turn_consent and profile_learning (file and line), in oauth_mcp (`decisions.ts`, which does not exist) and in the relay machine list were replaced by function names. The turn_consent notes now name `directReplyCollectable` and `storedReplyAdmitted` ([signedInbox](../signedInbox.md)) in place of `collectGate`, which does not exist. Still stale: the file and line references in the bodies of relay and runtime_ops; the short line references (`K:`, `H:`, `T:`, `PF:`) in oauth_mcp and profile_learning; the long file and line references in oauth_mcp (`api.ts:681-697`, `serve.ts:91-94`, `serve.ts:106`, `hooks.ts:69-70`, `handler.ts:90-93`; `packages/mcp/src` has no `serve.ts`); the `decisions.ts` and `collectGate` references in auth_edge, cloud_auth, outbound_queue, join_age and safety_trust; and the relay OPEN DRIFT note, which names `swapPlan` and `flushSwapShares`, two functions that are not on this branch. A model comparison replaces each such reference with a function name and fixes or records each drift.

## Run the models

```bash
pnpm run spec:setup
pnpm run quint:check                         # typecheck, replay traces, simulate safety and reachability
pnpm run quint:check turn_consent            # one model
pnpm run quint:check --tangle-only           # write the model blocks to runs/quint-models/
pnpm run quint:check --verify --jobs 2       # include bounded Apalache checks, requires Java 17+
```

A `witness_*` assertion is the negation of an expected reachable state. A witness check passes when the simulator reaches that state and the assertion fails. Random simulation and bounded model checking cover the modeled states within the run bounds.

These models use mutable variables, actions, nondeterministic environment steps, or executable traces. Vibespec generates TypeScript from pure definitions and guards in top-level `spec/*.md`. Keep whole-flow checks here while moving pure policy definitions into the Vibespec specs. When a generated policy takes over a production decision, compare its behavior with the corresponding action guard and keep the sequence, failures, and retry behavior in the flow model.

The [source coverage ledger](baseline/coverage.md), [drift record](baseline/drift.json), [LemmaScript file list](baseline/LemmaScript-files.txt), and [Dafny proof sources](baseline/proofs/) record the original relationships among models, code, and obligations. The historical proof sources include manually added lemmas and are scoped to the original branch. Vibespec's checks prove its own generated modules and eligible source files.

The frontend and agent flows have no imported model in this directory. Their state machines are top-level Vibespec specs: [landing entry](../landingEntry.md), [site pages](../sitePages.md), [brand identity](../brandIdentity.md), [browser join](../browserJoin.md), [connector authorization pages](../authorizationPages.md), [connected assistants](../connectedAssistants.md), [agent signup](../agentSignup.md), [connector tools](../connectorTools.md), [agent entry](../agentEntry.md), [staff sign-in](../staffSignIn.md), [console navigation](../consoleNavigation.md) and [console workspace](../consoleWorkspace.md). [join_flow](join_flow.md) records the earlier join page that every site had. The other frontend specs add the view layer to [oauth_mcp](oauth_mcp.md), [console_views](console_views.md) and [staff_console](staff_console.md).
