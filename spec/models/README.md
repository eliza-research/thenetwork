# Quint flow models

The [product stories](../product/stories.md) describe the member and staff flows. This directory holds their existing standalone Quint state machines. Each Markdown file contains the flow, its safety scope, and one executable `quint` block. Change the Markdown source when you update a model.

The 31 modules came from `claude/quint-state-machines` at `30d950e1d6fa027a67b94cc6b03ba379dc923a63`. That source revision includes the latest local wave 4 model changes. Their comments document bounds, abstractions, code locations, excluded cases, and existing drift at that revision. The source revision also contains the research plan and findings referenced in comments. Code locations and results need a new comparison with the runtime on this branch.

## Run the models

```bash
pnpm run spec:setup
pnpm run quint:check                         # typecheck, replay traces, simulate safety and reachability
pnpm run quint:check turn_consent            # one model
pnpm run quint:check --tangle-only           # write the model blocks to runs/quint-models/
pnpm run quint:check --verify --jobs 2       # include bounded Apalache checks, requires Java 17+
```

A `witness_*` assertion is the negation of an expected reachable state. A witness check passes when the simulator reaches that state and the assertion fails. Random simulation and bounded model checking cover the modeled states within the run bounds.

These models use mutable variables, actions, nondeterministic environment steps, or executable traces. Vibespec generates TypeScript from pure definitions and guards in top-level `spec/*.md`. Keep whole-flow checks here while moving pure policy definitions into the Vibespec specs. When a generated policy takes over a production decision, compare its behavior with the corresponding action guard and keep the sequence, failures, and retry behavior in the flow model.

The [source coverage ledger](baseline/coverage.md), [drift record](baseline/drift.json), [LemmaScript file list](baseline/LemmaScript-files.txt), and [Dafny proof sources](baseline/proofs/) record the original relationships among models, code, and obligations. The historical proof sources include manually added lemmas and are scoped to the original branch. Vibespec's checks prove its own generated modules and eligible source files.

The frontend and agent flows have no imported model in this directory. Their state machines are top-level Vibespec specs: [landing entry](../landingEntry.md), [site pages](../sitePages.md), [brand identity](../brandIdentity.md), [browser join](../browserJoin.md), [connector authorization pages](../authorizationPages.md), [connected assistants](../connectedAssistants.md), [agent signup](../agentSignup.md), [connector tools](../connectorTools.md), [agent entry](../agentEntry.md), [staff sign-in](../staffSignIn.md), [console navigation](../consoleNavigation.md) and [console workspace](../consoleWorkspace.md). [Stories F37–F51](../product/stories.md#story-f37--know-which-app-i-am-joining) link to them. For the browser join page, which only peon.biz keeps, `browserJoin` is the current model. [join_flow](join_flow.md) records the earlier join page that every site had. The other frontend specs add the view layer to [oauth_mcp](oauth_mcp.md), [console_views](console_views.md) and [staff_console](staff_console.md). Those imported models still hold the server sequences.

### photos_rating comparison (2026-11-18)

Compared with `packages/platform/src/photos.ts`, `photo-upload-link.ts`, `packages/network/service/photoIntake.ts`, `service.ts` (`hooks().onForget`, `ageLowered`, `verifiedAdult`, `dropRatings`, `writeRating`, `verify`, the staff ban, `exportMember`) and `packages/platform/src/accounts.ts` (`recordAge`, `leave`, `deleteAll`). The imported model described fixes that exist only on the source branch (hidden rows, a locked show step, the photo sweep, `reconcileAges` in the purge, photo deletion on a failed age check, a conditional consent write). This branch has none of them. The model now follows this branch: bytes before the row, a live row at once, `erasePhoto` as bytes, row, rating, `deleteFor` before the network forget, no automatic recovery (a later age statement and a staff ban retry are the only resumes), the upload link with its consent box, and the appearance exclusion in `memberExportFacetAllowed`. The ban exception drift noted at import is closed: `onForget` has no ban exception on this branch.

Open code defects (each has a run test that reaches it; `safety` leaves out only its named residue):

- PR-D1 `PhotoService.upload`: the row write has no second `mayTake`, no person lock and no ordering against `deleteFor`. An upload by link that lands while a leave, delete everything or an age drop is erasing keeps the photo (`d1RowAfterAgeListKeptTest`, `d1RowDuringLeaveKeptTest`).
- PR-D2 `PhotoService.upload`: the count is read without a lock, so parallel uploads (one link use carries up to four photos, and links and texts can overlap) pass `uploadMaxPerPerson` (`d2CountRaceTest`).
- PR-D3 `PhotoService.upload` and `erasePhoto`: bytes are written before the row and erased before the row, and nothing sweeps. A crash leaves bytes with no row (never deleted, also after delete everything), a row with no bytes, or a rating of a deleted photo (`d3OrphanBytesTest`, `d3StaleRatingTest`).
- PR-D4 `NetworkService.verify`: a failed staff age check drops the rating and keeps the photos (`d4FailedAgeCheckKeepsPhotosTest`).
- PR-D5 `Accounts.recordAge` and `ageLowered`: a crash after `noteAge` keeps a minor's photos and rating until the person states an age again (`d5CrashAfterAgeCommitTest`).
- PR-D6 `PhotoIntake.consentAnswer`: YES PHOTOS writes back the whole membership it read with `putMembership`, so a staff ban that lands meanwhile becomes `active` again (`d6ConsentWriteUndoesBanTest`). `PhotoUploadLinks.redeem` uses the same snapshot write inside its transaction; the model treats that path as atomic.

Abstractions: one `rate()` at a time (the code can overlap two; the version-bound discard in `writeRating` keeps the newer score); the `missedRows` ghost also counts a row written for a person who is no longer eligible, even when a later `deleteFor` erases it.

### Identity models comparison (2026-11-18)

auth_edge, cloud_auth, join_age, join_flow and phone_identity were compared with this branch. Code locations in their comments now name functions; line numbers of the source branch were removed or marked as ad67275 references. None of the source-branch fix commits for auth_edge and join_age (SD-010, SD-013, SD-015, SD-054, SD-181, SD-380, SD-491, Q-join_age-2, Q-join_age-3 and others) is in this branch. Where the code does not have the fix, the model keeps the intended rule and the defect is listed here.

- phone_identity: follows the code. The normalizers are `normalizePhone` (platform) and `normalizeAddress`/`toE164` (blooio); the proved `phone-core.ts` does not exist here, so their contracts were checked by reading. A banned number still gets the STOP, HELP and app-leave answers (`checkLineBan`); the model leaves these compliance answers out.
- cloud_auth: follows the code. Closed drift: a text join gives the new person to every person-less session (`admitMembership`) instead of ending them; a carrier-aging guard on `recycleWith` (every proof of the number has expired) replaces the old revocation, and the W3-126 traces now show that an earlier holder's grant ends with its one-hour proof. `max-samples` is 40000 so that `witness_lateBanGrantValid` stays reachable. Open drift: the staging-local callback has no one-hour cap on the Cloud proof; the model uses one hour for every mode.
- auth_edge: closed drift: one proxy secret (no `PLATFORM_PROXY_SECRET_PREVIOUS` on this branch); rotation is two writes (merged in the model); a macro-step `rotateForkFast` keeps `witness_rotationFork` reachable. Open code defects:
  - AE-1 `OtpService.start`: each bucket is a separate `store.hit` transaction, so a request refused by a later bucket stays counted in the earlier ones (`otpRefusedNotCounted`). Low.
  - AE-2 web OTP start route and MCP `startOtp`: a banned number answers `{ ok: true }` before any bucket counts it, so it never gets 429 and the ban is visible by count. Low.
  - AE-3 `PgPeopleStore.admitMembership`: every person-less session of the number gets the new person. After number recycling, the earlier holder's live web session can export or leave the new holder's data (`staleSessionNoAct`); through `/api/join` with the marker from `/api/me` it can also make an age statement (`ageOnlyByOwner`). Medium.
  - AE-4 `Accounts.joinLocked` (BelowJoinAge): an under-13 web join leaves the number's person-less sessions and cookies (`under13NothingStored`). Low.
  - AE-5 `parseNetworkDelegation`: production refuses any Cloud issue time after the local clock; `cloudSignIn.md` allows 30 s (`cloudSkewTolerated`). cloud_auth records the code; one of the spec and the code must change. Low.
  - AE-6 `SessionService.authenticate`: the rotation writes the next row without a re-read, so a request in flight during "delete everything" can create a session for the erased number. Low.
- join_age: closed drift: the invite-only web exit records no age; `declineUnderAge` is now `recordAge` -> `onAgeLowered` -> `finishUnderageCleanup`. Open code defects:
  - JA-1 `NetworkService.join` (AskForName): an age with no name goes only to the pending row, so it is lost after a day (`lowestWins`, `minorNeverMatched`). Medium.
  - JA-2 `NetworkService.join` (AskForHome after the age check): an allowed age with an invalid home city is not recorded. Medium.
  - JA-3 `Accounts.joinLocked` (ReturnExisting): a repeated web join runs no join hook, so a membership with no network member answers success forever (`joinSuccessHasMember`). Medium.
  - JA-4 `Accounts.joinLocked` (JoinHookFailed): no `onForget`, so a network member made before the hook failed stays (`noOrphanMember`). Medium.
  - JA-5 `Accounts.joinLocked` (BelowJoinAge, no person): the phone's pending text join stays (`under13StoresNothing`). Low.
  - JA-6 `NetworkService.join` with `putMembership`: a live membership can get a new member id (`oneMemberPerApp`). Low.
  - Not compared again: the route rules, the unit age writes, the minor welcome and interview, the first-contact notice and the age-0 floor.
- join_flow: historical; the page files it names are removed and `browserJoin` is the current page model. The server seams agree: `/api/me` now gives `signupView` on every app (the server change JF-2 needed), `/api/join` answers `account_changed` for a wrong marker, and a live member gets the existing membership.
